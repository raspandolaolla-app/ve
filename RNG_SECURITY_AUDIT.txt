1. RESUMEN EJECUTIVO
------------------------------------------------------------------------------
Se ha implementado una arquitectura de generación de números aleatorios (RNG)
Server-Authoritative criptográficamente segura e inmutable en la plataforma 
RASPANDO LA OLLA / PULSOPLAY.

El servidor de base de datos Supabase / PostgreSQL actúa como la única fuente de
verdad (Single Source of Truth) para la aleatoriedad de la plataforma mediante la
extensión nativa pgcrypto y gen_random_bytes().

2. ARQUITECTURA DE SEGURIDAD IMPLEMENTADA
------------------------------------------------------------------------------
A. Fuente de Aleatoriedad Principal (Servidor PostgreSQL):
   - Extensión: pgcrypto
   - Primitiva: gen_random_bytes() (RNG criptográficamente seguro del SO/Kernel)
   - Funciones SQL:
     * fn_secure_rng_int(p_min INT, p_max INT): Algoritmo de extracción de 32-bits
       sin sesgo de módulo para enteros uniformes.
     * fn_secure_rng_shuffle_jsonb(p_array JSONB): Algoritmo Fisher-Yates
       criptográficamente seguro para barajado de cartas y fichas de dominó.

B. Fallback Cliente Seguro:
   - Web Crypto API (window.crypto.getRandomValues).
   - Sustitución total de Math.random() no seguro en todos los motores de juego.

C. Registro de Auditoría Inmutable (Ledger RNG):
   - Tabla public.rng_events con Row Level Security (RLS).
   - Campos: event_id, session_id, table_id, user_id, game_type, event_type,
     sequence_number, result, commitment_hash, idempotency_key, created_at.

D. Compromiso Criptográfico y Verificación de Imparcialidad (Provably Fair):
   - SHA-256 (commitment_hash) generado en servidor para cada resultado.
   - Idempotencia estricta mediante idempotency_key único por acción.
